# neurocpu (nc)

Эмулятор CPU, которым такт за тактом управляет саморастущая сеть геометрических нейронов без спайков.

В `runtime/nc.c` есть только железо: 12 регистров, флаги, стек, память, порт и 23 простые операции
(сложение, вычитание, сдвиги, сравнение и т.д.). Умножения, деления, разбора текста и таблицы микрокода там нет.
Каждый такт сеть читает состояние и выдаёт 27 бит управления: операцию, регистры, константу, следующий адрес.

## Запуск

    make
    ./nc_bin --model models/nc.bin --tcp 7777        # порт TCP на 127.0.0.1
    ./nc_bin --model models/nc.bin --pty             # виртуальный COM-порт, путь напечатает в stderr
    ./nc_bin --model models/nc.bin --serial /dev/ttyUSB0   # настоящий последовательный порт, 115200
    printf 'MUL 6 7\n' | ./nc_bin --model models/nc.bin    # stdin/stdout
    ./nc_bin --model models/nc.bin --full            # без отсечения, для сверки

## Команды порта

Каждая строка выполняется сразу. Текст разбирает сама сеть, символ за символом.

| Группа | Команды |
|---|---|
| CPU | `SET R1 5`, `PRINT R1`, `ADD a b`, `SUB a b`, `JMP n`, `JZ a n`, `JNZ a n`, `JLT a b n`, `HALT` |
| Программа | `PROG` ... строки ... `END`, затем `RUN`; переходы считают строки с нуля |
| Калькулятор | `MUL DIV MOD ABS MIN MAX POW`, выражения `2+3*(4-1)^2` или `CALC ...` |
| Теория чисел | `GCD LCM FACT FIB ISQRT PRIME` |
| Сложнее | `MODPOW a b m`, `NCR n k`, `NPRIME n`, `PHI n`, `DIGSUM n`, `COLLATZ n`, `MODINV a m` |

Аргумент: число или регистр `R0..R7`. Если первый аргумент регистр, результат записывается в него.
Ошибка: ответ `ERR`. Числа 64-битные со знаком, переполнение заворачивается.
Граничное значение -2^63 печатается неверно: микрокод берёт модуль через смену знака.

Пример программы (сумма 1..10):

    PROG
    SET R0 0
    SET R1 10
    ADD R0 R1
    SUB R1 1
    JNZ R1 2
    PRINT R0
    HALT
    END
    RUN

## Нейрон

    z = P x                 общие на весь слой k=8 осей
    f = W x + Q z² + b      у каждого нейрона своя квадрика в этих осях
    h = max(0, f)

Форма задаётся знаками и весами Q: плоскость, полоса, эллипсоид, гиперболоид.
Замеры: `bench/speed.c`, `bench/acc.py`.

## Рост

Сеть начинает с 12 нейронов. Когда ошибка перестаёт падать, новые нейроны садятся прямо на ошибочные состояния,
а время от времени добавляется слой. В конце слабые нейроны удаляются с дообучением (`compress`).
Старые навыки сохраняются полным повторением.

## Обучение

    cd nc && python3 train.py && python3 harden.py ../models/nc.bin
    python3 tests/check.py ./nc_bin models/nc.bin 200

Нужен PyTorch только для обучения. `nc_bin` зависит только от libc и libm.

Сеть учится по трассам эталонного микрокода `nc/micro.uasm`. Алгоритмы написаны человеком, сеть их не изобретает.

## Итоги последнего обучения

Модель `models/nc.bin`: 1169 нейронов, 3 слоя. Сверка через порт с эталоном на Python: 4640 из 4640.
Проверка устойчивости: атака на входы, не влияющие на решение, и 256 случайных шумов на состояние не нашли ошибок среди 22430 состояний.
Журналы: `models/train.log`, `models/harden.log`, сравнение с MLP `models/mlp.log`.

## Открытие навыков по примерам (`discover/`)

Без трасс и без эталонного кода этих навыков: задача дана только примерами вход -> ответ.
Сеть-подсказчик обучается на случайных программах и предсказывает, какие операции нужны; перебор в `synth.c` идёт в этом порядке.
Найденное проверяется на скрытых примерах и попадает в библиотеку как новая операция.

    cd discover && gcc -O3 -march=native -shared -fPIC synth.c -o libsynth.so -lm
    python3 learn.py --mode hyper     # geo: один проход, hyper: два прохода с рёбрами, mlp, blind
    python3 tocode.py hyper.s4.json MUL,POPCOUNT,ILOG2,SUMTO,FACT   # в микрокод, nc/found.uasm
    cd ../nc && python3 harden.py ../models/nc2.bin                 # дообучение контроллера

Новые команды модели `models/nc2.bin`: `XA` умножение, `XB` число единиц, `XC` log2, `XD` сумма 1..n, `XE` факториал (только натуральные).

Два прохода: первый активирует фигуры и получает контекст по рёбрам активных фигур, второй считает фигуры на x + контекст.
Сделано в сети-подсказчике (`--mode hyper`) и в `bench/twopass.py`. Управляющая сеть CPU пока однопроходная.

## Учёба и работа (главный режим)

Учёба: учитель показывает навык обычной функцией на простом Python, навык сразу попадает в процессор как фигуры памяти.

    ./nc_bin --tcp 7777 &
    python3 nc/teacher.py tests/lessons.py 7777 models/skills.mem

Файл уроков показывается целиком за сессию на свежем запуске. Навыки могут вызывать друг друга и встроенные команды.

Работа: учитель не нужен.

    ./nc_bin --mem models/skills.mem
    TRIB 20                          команда
    gcd(REVDIG(21),SUMDIV(28))+1     навык внутри выражения
    ? 12 18 = 6; 7 21 = 7; 100 75    навык не назван, только примеры
    ?SEQ 1 5 14 30 55                продолжить ряд
    PROG ... TRIB R2 ... END / RUN   навык в программе

Проверка: `python3 tests/school.py`.
Выбор навыка для `?` сейчас делает перебор планов в `runtime/work.h`; выполнение каждого плана идёт под управлением сети.
Новые навыки хранятся как фигуры памяти, это точные шаблоны состояний, а не обобщающая плотная сеть.

## Сеть выбирает навык (`--planner`)

    python3 nc/practice.py            # практика, сохраняет models/planner.bin
    ./nc_bin --mem models/skills.mem --planner models/planner.bin

По примерам задачи сеть предсказывает навыки, аргументы и форму плана; планы пробуются по убыванию оценки.
Если они не подошли, включается перебор. Проверка: `python3 tests/choose.py` (память опыта выключена).
Новый навык нужно добавить в таблицу `BI` в `nc/practice.py` и пройти практику заново.

## Заморозка и составные навыки

Обученные навыки заморожены: веса и фигуры не меняются, попытка их перезаписать отклоняется. Новые навыки это формулы над старыми:

    DEF K1(a) = FIB(a)+DIGSUM(a)
    DEF K3(a) = s = SUMDIV(a); d = DIVCOUNT(a); s*d-a     цепочка шагов
    DEF K4(a) = K1(a)*2+K3(a)                             формула из формул
    ? 3 = 5; 7 = 16; 12 = 148; 20                         найти план по примерам
    SAVE L1                                               сохранить найденный план как навык
    @HASH                                                 контрольная сумма весов (сравнивать в одном запуске)
    @SAVE файл                                            сохранить навыки

Формулы раскрываются на входе порта, поэтому внутри `PROG` они пока не работают. Циклы формулой не выразить: для них нужен урок учителя.
Проверка: `python3 tests/compose.py`.

## Пирамида навыков (`pyramid/`) — основная архитектура нейропроцессора

Навык это своя небольшая группа геометрических нейронов. Внизу настоящие инструкции CPU (`and or xor add sub shl shr lt eq load`), поэтому арифметика точна всегда.
Новый навык обучается только вызывать навыки ниже; после экзамена его нейроны заморожены, нижние навыки в обучении вообще не участвуют.
Активна только сеть текущего навыка, поэтому один шаг считает всего несколько нейронов.

    cd pyramid && gcc -O3 -march=native -ffast-math npu.c -o npu
    python3 build.py                 # все уроки из lessons.py
    python3 build.py --extend more.py     # новые навыки поверх готовых, нижние байты файла не меняются
    printf 'SORTED 1 2 3\nGCD 48 18\n' | ./npu pyramid.bin
    python3 check.py                 # экзамен через порт

### Порт, выражения и выбор навыка в пирамиде

Теперь `npu.c` содержит только железо: кадры регистров, память, порт, настоящие инструкции, вызов навыков, перехват ошибок. Разбор строк, выражения, печать чисел, сообщения `ERR`, главный цикл — это навыки в `lessons.py` (уровни 6–19). Выбор навыка: уровни 12–17 и сеть `planner.bin`.

    python3 build.py && python3 planner.py        # пирамида, затем верхняя сеть
    python3 build.py --extend more.py             # новые навыки, старые байты не меняются
    printf 'fib(10)+gcd(12,18)*2\nDIV -7 2\nSORTED 1 2 3\n? 12 18 = 6; 7 21 = 7; 48 36\n?SEQ 1 5 14 30 55\n' | ./npu pyramid.bin
    python3 check.py pyramid.bin

Аргументы команды через пробел: число, функция или скобки (`MUL (2+3) 4`). Команды `PROG/RUN` здесь нет: новое поведение показывается уроком.

### Управление обновлениями (как в GERON)

`operations.json` это манифест операций GERON; `python3 mktab.py` переводит его в данные `update.tab`. Планирование с минимальной ценой, подтверждение и восстановление это навыки уровней 22–28, git, dotnet и aspire выполняет сценарий `device.sh` с настройками `device.conf`.

    UPDATE     прочитать состояние, показать план
    APPROVE    выполнить показанный план один раз; при сбое показать план восстановления
    CANCEL     отменить план
    STATUS     текущие факты

Проверка: `python3 update_check.py` (настоящий git, dotnet и aspire в тесте заменены заглушками).

### Windows

В папке `pyramid` лежит готовый `npu.exe`. Нужны git, .NET SDK и Aspire CLI в PATH.

    copy device.json.example device.json     (формат тот же, что geron.runtime.json)
    run.bat                                  ввод с клавиатуры
    run_port.bat                             порт TCP 127.0.0.1:7777

Запускайте из папки `pyramid`: рядом должны лежать `pyramid.bin`, `planner.bin`, `update.tab`, `device.ps1`, `device.json`. Другой проект из `device.json` выбирается переменной `NPU_PROJECT`.
Сборка exe: `python -m ziglang cc -target x86_64-windows-gnu -O3 -ffast-math -mcpu=x86_64_v2 npu.c -o npu.exe -lws2_32 -lm`.
